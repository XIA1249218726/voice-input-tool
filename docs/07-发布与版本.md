# 发布与版本

## 1. 发布前检查

- [ ] `scripts\test.ps1` 通过
- [ ] 源码自检通过（有麦克风的机器）
- [ ] 更新 `CHANGELOG.md`，把 Unreleased 改为新版本
- [ ] 同步版本号（见下）
- [ ] README 的截图 / 功能表与新版本一致
- [ ] 不提交模型、`dist/`、`config.json`、API Key
- [ ] 安装包可以静默安装/卸载
- [ ] 在干净 Windows 机器上试运行（可选但推荐）

## 2. 版本号位置

| 文件 | 字段 |
| --- | --- |
| `app/paths.py` | `APP_VERSION = "1.0.0"` |
| `build/version_info.txt` | `filevers`、`prodvers`、`FileVersion`、`ProductVersion` |
| `build/installer.nsi` | `APP_VERSION`、`VIProductVersion` |
| `build/build_installer.ps1` | `-Version` 默认值 |
| `README.md` / `README.en.md` | 下载文件名中的版本（如需要） |
| `CHANGELOG.md` | 新版本段落 |

## 3. 打标签并发布

```powershell
git add .
git commit -m "release: v1.0.1"
git tag v1.0.1
git push origin main
git push origin v1.0.1
```

推送 tag 后，`.github/workflows/release.yml` 会：

1. 在 `windows-latest` 上安装依赖；
2. 下载模型并构建便携版；
3. 安装 NSIS 并构建安装程序；
4. 打包 `VoiceInputTool-1.0.1-portable.zip`；
5. 创建 Release，上传：
   - `VoiceInputTool-Setup-1.0.1.exe`
   - `VoiceInputTool-1.0.1-portable.zip`

首次发布前，在仓库 **Settings → Actions → General** 确认
「Workflow permissions」允许读写，否则 Release 上传会失败。

## 4. Release 文案模板

```markdown
## 语音输入工具 v1.0.1

### 变更
- ...

### 下载
- `VoiceInputTool-Setup-1.0.1.exe`：安装版（推荐，当前用户安装，无需管理员）
- `VoiceInputTool-1.0.1-portable.zip`：便携版

### 说明
- 完全离线识别，录音不出本机
- 未签名，首次运行可能触发 SmartScreen
- 游戏内打不出字请以管理员身份运行

**完整更新日志：** CHANGELOG.md
```

## 5. 代码签名（可选）

未签名 exe 可能被 SmartScreen 拦截。若购买代码签名证书：

```powershell
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 `
  /f cert.pfx /p $env:CERT_PASSWORD `
  "dist\语音输入工具\语音输入工具.exe"
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 `
  /f cert.pfx /p $env:CERT_PASSWORD `
  "dist\VoiceInputTool-Setup-1.0.1.exe"
```

在 GitHub Actions 中把证书放进 Secrets（如 `WINDOWS_CERT_PFX_BASE64`、
`WINDOWS_CERT_PASSWORD`），在 Release 工作流构建后解码并签名，再上传。

## 6. 发布后

- 在 README 顶部确认 Releases 链接可用；
- 给仓库加 Topics（见 `PUBLISH.md`）；
- 观察 Issue / Discussion；
- 如果发现严重问题，发布 `v1.0.2` 修复，不要删除旧 Release。
