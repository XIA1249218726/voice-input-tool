# 架构与数据流

## 1. 目标与约束

这是一个 Windows 桌面语音输入工具，核心约束：

- **低延迟**：从松开快捷键到文字上屏，目标 < 0.5 秒；
- **离线优先**：默认模型在本机运行，录音不出本机；
- **不依赖输入法**：中文通过 `KEYEVENTF_UNICODE` 逐字注入，绕过输入法；
- **不污染系统**：便携 / 当前用户安装，不写服务、不装驱动；
- **可恢复**：麦克风、模型、热键任一失败都要能明确报错，而不是假装在运行。

## 2. 总体结构

```
┌──────────────────────────── GUI (tkinter, 主线程) ────────────────────────────┐
│  使用页：状态灯 / 最近识别 / 日志 / 录音测试       设置页：热键、麦克风、引擎      │
│         ▲ queue.Queue 事件（log/state/text/error/ready）                         │
└─────────┼──────────────────────────────────────────────────────────────────────┘
          │
┌─────────┴──────────────── VoiceService（业务状态机） ─────────────────────────┐
│  start(): 加载 ASR → 打开麦克风 → 安装热键 → 启动识别 worker                    │
│  状态：IDLE ──按下──▶ RECORDING ──松开/超时──▶ BUSY ──识别完──▶ IDLE             │
│                                                                                │
│  HotkeyManager（pynput 监听线程）      Recorder（PortAudio 回调线程）            │
│        │ 按下/松开                          │ 100ms/块，预录 300ms                │
│        ▼                                    ▼                                   │
│  _begin_recording / _finish_recording ── 裁剪静音 ──▶ jobs 队列                  │
│                                                    │                           │
│                                          ASR worker 线程                       │
│                                          local: sherpa_onnx                   │
│                                          cloud: requests                      │
│                                                    │                           │
│                                          postprocess（修正词/标点/前缀）         │
│                                                    ▼                           │
│                               WinAPI：剪贴板 或 SendInput 打字 + 回车            │
└────────────────────────────────────────────────────────────────────────────────┘
```

## 3. 线程模型

| 线程 | 创建位置 | 职责 | 同步方式 |
| --- | --- | --- | --- |
| Tk 主线程 | `gui.run()` | 界面、事件轮询、配置保存 | 只通过 `queue.Queue` 接收后台事件 |
| 启动线程 | `gui.start_service()` | 加载模型、打开麦克风（耗时 1~2 秒） | 完成后 `root.after(0, ...)` |
| 热键监听 | `HotkeyManager.start()` | 全局键盘/鼠标钩子 | 自身 `_lock` 保护 `_active/_mods` |
| 音频回调 | `sounddevice.InputStream` | 拷入数据块、维护预录队列 | `Recorder._lock` |
| 识别 worker | `VoiceService.start()` | 逐条识别 jobs、后处理、输入 | `queue.Queue` |
| 录音超时 | `threading.Timer` | 到达 `max_record_seconds` 自动结束 | 回调走服务锁 |
| 提示音 | `_beep()` | `winsound.Beep` | 独立守护线程，避免阻塞 |

关键点：

- 音频回调里**不做任何耗时操作**，只 copy + append；
- 识别不在音频回调或热键回调里做，避免阻塞输入；
- 所有 GUI 更新都回到主线程（或经由队列轮询）。

## 4. 一次完整的数据流

1. 用户按下热键 → `pynput` 监听线程调用 `_on_press`；
2. `VoiceService._begin_recording()` 在锁内检查 `ready && state == IDLE`，状态置 `RECORDING`；
3. `Recorder.start()` 把预录队列（约 300 ms）作为开头，开始累积数据块；
4. 用户松开 → `_finish_recording()`：
   - 状态置 `BUSY`；
   - `Recorder.stop()` 取出全部 PCM；
   - `trim_silence()`：10 ms 分帧算 RMS，10% 分位估计噪声，双阈值 VAD 裁首尾，
     太短/全静音返回 `None`；音量过小做有限增益；
5. 裁剪后的数据进入 `_jobs` 队列；
6. worker 取出 → `engine.transcribe()`（本地 sherpa-onnx / 云端 HTTP）；
7. `postprocess()`：去 SenseVoice 标签、应用修正词、去句末标点、加前缀；
8. `_deliver()`：按配置决定“复制剪贴板”还是“开聊天框 → 逐字 SendInput → 发送”；
9. 状态回 `IDLE`，响一声完成提示音。

## 5. 启动与停止

`VoiceService.start()` 的提交顺序很重要：

1. 载入模型（失败 → 报错、`ready=False`）；
2. 打开麦克风（失败 → 关流、报错、`ready=False`）；
3. 校验热键（单独修饰键或非法键 → 报错）；
4. 启动热键监听（失败 → 关麦克风、报错）；
5. 最后才在锁内一次性发布 `_engine/_recorder/_hotkey/_worker` 并置 `ready=True`。

这样 GUI 只认 `service.ready`，不会出现“麦克风没打开但按钮显示停止”的假运行状态。

`stop()` 的顺序：置 `_running/ready=False` → 停热键 → 给 worker 发哨兵并 join（最多 1.5 s）
→ 清空任务 → 关麦克风 → 释放引擎 → 发 `ready=False` 事件。

## 6. 路径模型

`app/paths.py` 把路径分成两类：

| 类型 | 源码运行 | 安装版 |
| --- | --- | --- |
| 资源（模型、图标） | 项目根目录 | exe 所在目录 |
| 数据（config、logs） | 项目根目录 | `%LOCALAPPDATA%\VoiceInputTool` |

数据目录选择顺序：

1. `VOICE_DATA_DIR` 环境变量；
2. `portable.flag` 存在 → exe 目录（绿色版）；
3. `%LOCALAPPDATA%\VoiceInputTool`（会实际写探针文件验证可写）；
4. `exe\userdata`；
5. `%TEMP%\VoiceInputTool`。

`config.py` 在导入时缓存这些路径；`CONFIG_PATH/MODEL_DIR/LOG_DIR` 对外保持旧名称，
其余模块不需要知道是否打包。

## 7. 打包结构

```
语音输入工具\
├─ 语音输入工具.exe          PyInstaller 引导器（windowed）
├─ _internal\                 Python 运行时、依赖、Tk、DLL
├─ models\sense-voice\        模型（不打进 exe，安装时并列放置）
├─ app.ico
├─ 使用说明.txt
├─ 自检.bat
├─ config.example.json
└─ uninstall.exe             仅安装版
```

模型不打进 PyInstaller 归档的原因：

- 单文件模式每次启动都要把 228 MB 解压到临时目录，启动很慢；
- onedir 下模型作为普通文件安装，读取直接走文件缓存；
- 安装包用 NSIS 的 solid LZMA 压缩，体积仍然可控。

## 8. 失败处理策略

| 失败点 | 行为 |
| --- | --- |
| 模型缺失/损坏 | 启动失败，界面报错，`ready=False` |
| 麦克风占用/设备不存在 | 启动失败；设备名匹配不到时回退系统默认并给出提醒 |
| 热键非法或被占用 | 启动失败并提示重新设置 |
| 识别失败 | `error` 事件 + 日志，状态回 IDLE，可继续下一次 |
| 按键注入被拒 | 自动复制到剪贴板并在日志说明 |
| 剪贴板被占用 | 重试 5 次，失败写日志 |
| 配置 JSON 损坏 | 用默认值启动，不崩溃 |
| 启动崩溃 | 写 `logs/crash.log`，弹 MessageBox |
