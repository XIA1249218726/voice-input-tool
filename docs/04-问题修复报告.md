# 问题修复报告（1.0.0）

本次在原有可运行版本上做了静态审查、实际运行和打包验证，修复了以下问题。
按影响从高到低排列。

## 1. 64 位 Win32 句柄被截断（高）

**现象**：在某些 64 位进程中，`foreground_exe()` 可能返回空，导致“仅在游戏窗口激活时输入”
永远判定失败，识别结果只进剪贴板，游戏里永远不出字；单实例激活旧窗口也可能无效。

**根因**：`ctypes.WinDLL` 的默认返回类型是 32 位 `int`。`GetForegroundWindow` 返回 `HWND`、
`OpenProcess` 返回 `HANDLE`，如果不声明 `restype`，ctypes 会把 64 位句柄截成 32 位。
虽然 Windows 句柄值通常落在低 32 位，但这不是 API 保证的行为。

**修复**：

- `app/winapi.py`：为 `SendInput`、`GetForegroundWindow`、`GetWindowTextLengthW`、
  `GetWindowTextW`、`GetWindowThreadProcessId`、`OpenProcess`、
  `QueryFullProcessImageNameW`、`CloseHandle`、`GlobalAlloc/GlobalLock/GlobalFree`、
  剪贴板函数全部声明 `argtypes/restype`；
- `main.py`：为 `CreateMutexW`、`CloseHandle`、`FindWindowW`、`ShowWindow`、
  `SetForegroundWindow`、`MessageBoxW` 声明原型，并用 `use_last_error=True` +
  `ctypes.get_last_error()` 判断 `ERROR_ALREADY_EXISTS`。

**验证**：自检和实际运行中前台进程路径可正确读取；单实例第二次启动能把窗口置前。

## 2. 启动失败却显示“运行中”（高）

**现象**：麦克风被占用/拔掉时，模型已加载但服务未真正启动，界面按钮却显示“停止”，
状态灯仍是“待命”，按热键没有任何反应。

**根因**：`gui._after_start()` 只用 `service._engine is not None` 判断是否就绪；
麦克风打开失败时 `_engine` 已赋值，因此误判。

**修复**：

- `VoiceService` 增加公开的 `ready` 状态，只有模型、麦克风、热键全部成功后置 True；
- 启动顺序调整为“全部准备好后再一次性发布”，失败路径清理已打开的资源；
- GUI 改为读取 `service.ready`，失败时回到“开始”，状态显示“未启动”。

## 3. 录音缓冲无上限（中）

**现象**：长时间按住热键（超过 `max_record_seconds`）时内存持续增长；定时器失效或
测试模式录长音频时更明显。

**根因**：音频回调只把 `overflowed` 置 True，仍然继续 `append`。

**修复**：`Recorder` 预计算最大块数，达到上限后不再追加，只保留溢出标记。

## 4. 剪贴板写入失败/内存泄漏（中）

**现象**：剪贴板被其它程序短暂占用时，识别结果丢失；偶发失败后进程持有未释放的全局内存。

**根因**：`OpenClipboard` 失败直接 return，`GlobalAlloc` 的句柄没有 `GlobalFree`；
`SetClipboardData` 的返回值也未检查。

**修复**：失败路径统一 `GlobalFree`；`OpenClipboard` 重试 5 次（30 ms 间隔）；
检查 `SetClipboardData`；成功后把所有权交给系统，避免双重释放。

## 5. 配置可能写坏 / 手改配置导致崩溃（中）

**现象**：保存瞬间断电/崩溃会留下半截 JSON，下次启动全部设置丢失；
手工把 `chat_open_delay` 写成字符串会让程序启动即异常。

**修复**：

- 保存改为临时文件 + `fsync` + `os.replace` 原子替换；
- 读取时按字段默认类型做转换，非法值回退默认；
- 对热键、语言、引擎、模式、延迟、线程数、录音时长做范围/枚举校验。

## 6. 安装到 Program Files 后配置无法保存（中）

**现象**：旧版把 `config.json` 固定放在程序目录；安装到只读目录时保存失败。

**修复**：新增 `app/paths.py`，安装版默认写 `%LOCALAPPDATA%\VoiceInputTool`；
通过写探针选择可写目录，并支持 `VOICE_DATA_DIR` 和 `portable.flag`。
同时保留 exe 旁旧配置的自动迁移。

## 7. 虚拟声卡提醒永远不触发（低）

**现象**：日志里的“当前是虚拟声卡”提醒在默认设备下从不出现，即使默认设备就是 MIXLINE。

**根因**：判断的是 `cfg.device`，默认设备时为空字符串。

**修复**：改用 `Recorder.active_device`（实际打开的设备）匹配关键字，并在配置的设备
找不到时提示“已改用系统默认”。

## 8. 热键监听线程竞态（低）

**现象**：快速按组合键偶尔不触发或提前结束。

**根因**：pynput 回调线程修改 `_mods`，而 `_fire_press/_fire_release` 在另一把锁下读取，
修饰键集合没有一致保护。

**修复**：`_kb_press/_kb_release` 对 `_mods` 的读写加 `_lock`；单独修饰键判定为非法热键。

## 9. 界面高分屏发虚 / 位置偏移（低）

**修复**：创建 Tk 前调用 `SetProcessDpiAwareness(1)`（失败回退 `SetProcessDPIAware`）；
窗口按屏幕尺寸居中；任务栏 AppUserModelID 和图标沿用应用自己的图标。

## 10. 打包版没有控制台，自检不可见（中，打包相关）

**现象**：windowed exe 的 `sys.stdout` 为 None，`--selftest` 直接 `print` 会失败，
用户无法确认依赖/模型是否正常。

**修复**：

- CLI 模式下 `AttachConsole(ATTACH_PARENT_PROCESS)`，没有父控制台则 `AllocConsole`；
- `selftest` 的每一行同时写入 `logs/selftest.txt`，并做 stdout 缺失兜底；
- 安装包附带 `自检.bat`，用 `start /wait` 等待进程结束，再显示 UTF-8 报告。

## 11. 打包/安装相关修复

- 新增 `app/paths.py` 解决 frozen 后 `__file__` / 可执行文件路径差异；
- `resource_root()` 使用 `sys.executable` 所在目录，模型与 exe 并列；
- PyInstaller 显式收集 `sherpa_onnx`、`sounddevice`（PortAudio DLL）、`pynput`、
  `requests`、`certifi`，并附加图标和版本资源；
- NSIS 脚本改用 UTF-8 BOM，避免 `Bad text encoding`；
- 编译 NSIS 时把 `TMP/TEMP` 指向项目内，避免受限环境无法建 mmap。

## 回归验证

- 17 个单元测试全部通过（配置、裁剪、WAV、后处理、热键、真实中文识别）；
- 源码版 `--selftest`：依赖、模型、麦克风、模型加载全部通过；
- 打包版 `--selftest`：exit 0，报告写入数据目录；
- 打包版 GUI 可启动、识别引擎加载成功、窗口标题/图标正确、可正常关闭；
- 安装程序静默安装到测试目录后，文件完整、可运行、可卸载。
